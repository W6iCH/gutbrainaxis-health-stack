# 管理控制台 设计说明

> 组件位置：`services/admin_console/`｜默认端口 **9000**｜入口 `app.py`
> 版本：Admin Console v6（可发布版）｜日期：2026-09-16

---

## 1. 技术选型与理由

| 选择 | 理由 |
|---|---|
| **Flask 3.x**（Python） | ① 与课题原有 `admin_console.py` 同栈，运维与二次开发成本最低；② 依赖极少（Flask + Werkzeug），`requirements.txt` 只 3 行，离线内网可安装；③ 与本项目其余服务（`feedback_server.py`、`data_dashboard/app.py`）统一用 Python，团队无需引入新语言/JVM/Node 运行时 |
| **原生 JS + 原生 CSS**（无框架、无 CDN） | 内网服务器常无外网出口；把 `app.js` / `app.css` 放本地 `static/`，**离线可用**。避免 React/Vue 构建链，降低发布包体积与维护面 |
| **内联模板**（`render_template_string`） | 控制台是单页壳 + 纯 API 前端，无需 Jinja 模板目录；少一层文件依赖，安装时不易出现"模板缺失" |
| **参数列表调用系统命令**（`subprocess([...])`，非 shell 拼接） | 杜绝命令注入；服务名走白名单 `SERVICE_WHITELIST` |
| **systemd 优先 + DRY_RUN 降级** | 生产用 systemd 管进程；开发/CI 用 `DRY_RUN=1` 模拟，无需 root 即可端到端自测 |
| **不做 WSGI 生产服务器**（当前 `app.run`） | 与其余服务保持一致、零额外依赖。**默认只监听 127.0.0.1**，如需更高并发建议前面加 Nginx（已含反代模板）或改 gunicorn |

### 模块划分

```
services/admin_console/
├── app.py               # 应用入口：路由 / 请求守卫 / SPA 外壳 / 首次引导
├── auth.py              # 口令哈希、会话、登录限速、API Key
├── config_manager.py    # .env 读写 / 校验 / 备份 / 恢复默认
├── service_manager.py   # systemd(supervisor/PID 降级) start/stop/restart/enable/disable
├── port_manager.py      # 端口与反代映射：冲突检测 → 预览 → nginx -t → reload → 回滚
├── health_check.py      # 服务探活 / 日志尾（白名单）/ DB 可读写
├── audit.py             # 审计日志（时间/事件/操作人/结果/变更摘要）
├── static/app.css       # 样式（本地，无 CDN）
├── static/app.js        # 前端逻辑（本地）
├── config/console.env.example
└── requirements.txt
```

**可移植性**：基准路径全部来自环境变量 —— `APP_BASE`（服务目录，默认 `/opt`）、
`CONFIG_DIR`、`LOG_DIR`、`NGINX_SITES_DIR`、`NGINX_ENABLED_DIR`；
未设置时回退到脚本所在目录。代码内**无个人绝对路径**。

## 2. 功能清单与接口

### 2.1 配置管理

| 能力 | 说明 |
|---|---|
| 读取/写入 `.env` | `GET /api/config`（回显时自动剔除 `SECRET_KEY`、`SMTP_PASSWORD`）｜`POST /api/config` |
| 校验 | 端口范围 1–65535、邮箱格式、必填项、路径存在性/可写性 |
| 原子写 | 临时文件 + `os.replace`；写前自动备份 `.env.bak.<时间戳>` |
| 恢复默认 | `POST /api/config/restore` —— 从 `config/*.example` 还原 |

### 2.2 进程开关

| 能力 | 说明 |
|---|---|
| 状态 | `GET /api/processes` —— active/inactive/failed、enabled/disabled、PID、启动时间、内存 |
| 操作 | `POST /api/processes/<service>/<action>`，action ∈ `start / stop / restart / enable / disable` |
| 安全 | `subprocess` 参数列表 + `SERVICE_WHITELIST` 白名单；无 systemd 时降级 supervisor/PID 文件 |
| DRY_RUN | `DRY_RUN=1` 时只回显将执行的命令，不改系统 |

### 2.3 端口映射与反向代理

| 能力 | 说明 |
|---|---|
| 查询 | `GET /api/ports` —— 各服务当前监听端口与反代映射 |
| 变更预览 | `POST /api/ports/preview` —— 返回将写入的**完整** Nginx 配置与差异，不落盘 |
| 应用 | `POST /api/ports/apply` —— 落盘 → `nginx -t` → 通过才 `systemctl reload nginx` |
| 冲突检测 | 端口重复、端口已被占用（`ss -tlnp` / socket 探测）、域名重复 → `PortConflictError` |
| 回滚 | `nginx -t` 失败 → 自动还原上一版配置并报错；不执行 reload |

**落地流程（这是本模块的关键契约）**

```
用户在界面改端口/域名
        ↓
① 校验与冲突检测（重复 / 占用 / 非法值）—— 不通过则直接返回错误，不动任何文件
        ↓
② 生成完整 Nginx 配置文本 → 返回「变更预览」给用户确认
        ↓
③ 用户确认 → 备份现有配置（<file>.bak.<ts>）→ 原子写入新配置
        ↓
④ nginx -t 语法与语义校验
        ├─ 失败 → 还原备份 → 返回错误（不 reload，服务不受影响）
        └─ 通过 → systemctl reload nginx（平滑 reload，不断连接）
        ↓
⑤ 写审计日志（端口/域名 变更前 → 变更后）
```

### 2.4 自检面板

| 能力 | 接口 |
|---|---|
| 服务探活（HTTP + 端口，含响应码/耗时） | `GET /api/health` |
| 日志尾查看（白名单日志键，限行数，禁路径穿越） | `GET /api/logs/list`、`GET /api/logs/<log_key>` |
| 数据库可读写检查 | 并入 `GET /api/health` |
| 主机资源（CPU/内存/磁盘/负载） | `GET /api/system` |

### 2.5 审计日志

`GET /api/audit` 读取最近 N 条。写入格式（`logs/console_audit.log`）：

```
[2026-09-16 03:50:18] EVENT=login OPERATOR=admin RESULT=success BEFORE=管理员登录 AFTER= DETAIL=-
[2026-09-16 03:50:19] EVENT=password_change OPERATOR=admin RESULT=success BEFORE=口令已更新 AFTER= DETAIL=-
```

覆盖事件：`login` / `logout` / `password_change` / `setup` / `config_update` /
`config_restore` / `process_action` / `nginx_apply`。

## 3. 鉴权设计

| 项 | 实现 |
|---|---|
| 口令存储 | `werkzeug.security.generate_password_hash` / `check_password_hash`（pbkdf2）写入 `config/passwd`，权限 **600** |
| 首次初始化 | 启动时若未设置口令：**自动生成随机初始口令** → 写 `config/initial_password.txt`（**权限 600**）→ 同时打印到启动日志；并写入 `.must_change_password` 标记 |
| 强制改密 | 标记存在时，除 `/api/change_password`、`/api/logout`、`/api/login_status` 外的所有 `/api/*` 返回 **403 `MUST_CHANGE_PASSWORD`**；改密成功后自动删除初始口令文件与标记 |
| 备用初始化 | `POST /api/setup`（仅在未安装时可用）；已安装返回 409 |
| 会话 | 签名 Cookie；`SECRET_KEY` 来自配置或首次运行生成并落盘 `config/secret_key`（600） |
| 请求守卫 | `before_request`：非白名单 `/api/*` 未登录 → 401 `UNAUTHORIZED` |
| CSRF | 写操作一律 POST + 同源校验；Cookie 为签名会话 |
| 登录限速 | 按来源 IP 记录失败时间窗，超阈值锁定 |
| 网络暴露 | 默认 `CONSOLE_HOST=127.0.0.1`（仅本机）。**如需内网访问显式改为内网地址；不要直接暴露公网**，公网请走 Nginx + HTTPS + 额外访问控制 |

## 5. 已知限制与后续建议

| 限制 | 建议 |
|---|---|
| 使用 Flask 开发服务器 | 本机/内网小流量足够；如需加固，改 gunicorn 或置于 Nginx 之后并限并发 |
| 无多用户/角色 | 当前单管理员模型。如需多人，扩展 `auth.py` 的用户表与角色 |
| 前端无构建链 | 换来离线可用与零依赖；功能扩展时注意 `app.js` 体积 |
| 端口变更即时生效 | 已做预览 + `nginx -t` + 回滚；建议变更窗口避开被试集中填答时段 |
