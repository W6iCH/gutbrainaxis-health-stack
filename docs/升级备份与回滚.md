# 升级、备份与回滚

> 适用版本：gutbrainaxis-health-stack 一键部署包（2026-09 发布版）
> 最后更新：2026-09-16
> 前置阅读：[`安装说明.md`](./安装说明.md)

本文档覆盖系统日常运维中的三个核心操作：数据备份、版本升级、异常回滚。

---

## 1. 备份

### 1.1 使用备份脚本

系统提供了 `scripts/backup.sh` 备份脚本，支持一键备份数据库+配置文件。

```bash
# 默认备份到 $INSTALL_ROOT/backups/
sudo bash scripts/backup.sh

# 指定备份目录
sudo BACKUP_DIR=/data/backups bash scripts/backup.sh

# 指定保留份数（默认保留最近 14 份）
sudo RETENTION=30 bash scripts/backup.sh
```

### 1.2 备份内容

脚本自动备份以下内容：

| 项目 | 说明 |
|------|------|
| 数据库文件 | 问卷数据库 (`survey_data.db`)、饮食数据库 (`diet_data.db`) |
| 配置文件 | `/etc/research-app/env`、`/root/.config/rclone/rclone.conf`、systemd 单元文件 (`research-*.service`、`research-*.timer`) |
| 打包格式 | tar.gz，文件名：`backup_YYYYMMDD_HHMMSS.tar.gz` |
| 保存位置 | `$INSTALL_ROOT/backups/` |

### 1.3 备份保留策略

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `RETENTION` | 14 | 保留最近 N 份备份，超出部分自动删除 |
| `BACKUP_DIR` | `$INSTALL_ROOT/backups` | 备份文件存放目录 |

### 1.4 手动备份命令

```bash
# 仅备份数据库
mkdir -p /data/backup
cp $INSTALL_ROOT/sjtu_survey_pro/survey_data.db /data/backup/
cp $INSTALL_ROOT/diet_survey/diet_data.db /data/backup/

# 仅备份配置
cp /etc/research-app/env /data/backup/
cp /root/.config/rclone/rclone.conf /data/backup/

# 备份全部
tar czf /data/backup/full-backup-$(date +%Y%m%d).tar.gz \
  $INSTALL_ROOT/sjtu_survey_pro/*.db \
  $INSTALL_ROOT/diet_survey/*.db \
  /etc/research-app/env \
  /root/.config/rclone/rclone.conf \
  /etc/systemd/system/research-*.service \
  /etc/systemd/system/research-*.timer
```

### 1.5 rclone 远程备份（自动）

系统还通过 `research-rclone-backup.service` + `.timer` 提供每日远程备份：

```bash
# 查看备份定时器
systemctl status research-rclone-backup.timer
systemctl list-timers | grep rclone

# 查看远程备份日志
tail -50 /var/log/rclone-backup.log
```

远程备份配置通过 `/root/.config/rclone/rclone.conf` 中的 **onedrive**（或 S3）远程存储定义。

> ⚠️ 注意：rclone 远程备份需要先在配置文件中填写有效的 `drive_id` 和 `token`。
>
> **手动触发远程备份：**
>
> ```bash
> sudo systemctl start research-rclone-backup
> ```

## 2. 升级

### 2.1 升级流程

#### 第 1 步：备份当前系统

```bash
sudo bash scripts/backup.sh
```

> ⚠️ **升级前必须备份**。确保至少有一份备份可用后再进行下一步。

#### 第 2 步：拉取新代码

```bash
cd /opt/gutbrainaxis-health-stack
git fetch origin
git log --oneline HEAD..origin/main    # 查看有哪些更新
git pull origin main
```

> 如果部署包是通过压缩包方式获取，解压覆盖到目标目录即可。

#### 第 3 步：重新运行安装脚本（幂等）

安装脚本是幂等的，重复执行不会破坏已有数据：

```bash
sudo bash install.sh --dry-run    # 先预览
sudo bash install.sh              # 正式安装
```

重新运行安装脚本会：

- **保留现有数据库**（不覆盖已有数据文件）
- **保留或更新配置文件**（已有 `env` 文件不覆盖，新版本增加的新配置项会追加）
- **更新 systemd 单元**（服务文件替换为新版本）
- **更新 Nginx 配置**（替换为新版本模板）
- **更新 Python 依赖**（根据新的 `requirements.txt` 安装/更新）

> 幂等性说明：在第 5 步（生成配置文件）中，若 `/etc/research-app/env` 已存在则跳过；若 `rclone.conf` 已存在也跳过。已有数据不受影响。

#### 第 4 步：运行自检

```bash
sudo bash verify.sh
```

确保所有检查项为 ✅。

#### 第 5 步：功能验证

登录管理控制台，检查各项服务是否正常运行。建议按以下清单逐项验证：

- [ ] 管理控制台可登录
- [ ] 问卷反馈服务可访问（`curl http://127.0.0.1:8000/`）
- [ ] 饮食反馈服务可访问（`curl http://127.0.0.1:8001/ping`）
- [ ] Webhook 存活检查（`curl http://127.0.0.1:9876/health`）
- [ ] Nginx 代理正常（`curl http://localhost/`）
- [ ] 数据库可读写

## 3. 回滚

### 3.1 三种回滚场景

回滚分为以下三个独立场景，根据需求执行：

#### 场景一：代码回滚（仅恢复服务程序）

```bash
cd /opt/gutbrainaxis-health-stack
git log --oneline -5               # 查看最近提交
git revert <坏提交哈希>            # 安全回滚（保留历史）
# 或
git reset --hard <好提交哈希>      # 强制回滚（丢弃历史，慎用）

# 重新运行安装脚本
sudo bash install.sh
```

#### 场景二：数据回滚（恢复数据库）

```bash
# 1. 停止服务
systemctl stop research-*

# 2. 查看可用备份
ls -t $INSTALL_ROOT/backups/backup_*.tar.gz

# 3. 解压指定备份
tar xzf $INSTALL_ROOT/backups/backup_20260915_120000.tar.gz -C /tmp/restore/

# 4. 恢复数据库文件
cp /tmp/restore/backup_20260915_120000_*.db $INSTALL_ROOT/sjtu_survey_pro/
cp /tmp/restore/backup_20260915_120000_*.db $INSTALL_ROOT/diet_survey/

# 5. 启动服务
systemctl start research-*
```

#### 场景三：配置回滚（恢复环境变量和 systemd 配置）

```bash
# 从备份中恢复配置文件
tar xzf $INSTALL_ROOT/backups/backup_*.tar.gz -C /tmp/restore/

# 恢复环境变量
cp /tmp/restore/backup_*_config/env /etc/research-app/env
chmod 600 /etc/research-app/env

# 恢复 systemd 配置
cp /tmp/restore/backup_*_config/research-*.service /etc/systemd/system/
cp /tmp/restore/backup_*_config/research-*.timer /etc/systemd/system/
systemctl daemon-reload

# 重启服务
systemctl restart research-*
```

### 3.2 完整回滚流程（三合一）

如需全部回滚（代码+数据+配置）：

```bash
# 1. 停服
systemctl stop research-*

# 2. 回滚代码
cd /opt/gutbrainaxis-health-stack
git reset --hard <上一个好版本>    # 确认当前是 git 仓库时使用

# 3. 恢复数据
tar xzf $INSTALL_ROOT/backups/backup_<时间戳>.tar.gz -C /tmp/restore/
cp /tmp/restore/*.db $INSTALL_ROOT/sjtu_survey_pro/
cp /tmp/restore/*.db $INSTALL_ROOT/diet_survey/

# 4. 恢复配置
CONF_RESTORE=/tmp/restore/backup_*_config
[ -d "$CONF_RESTORE" ] && cp "$CONF_RESTORE"/env /etc/research-app/
[ -d "$CONF_RESTORE" ] && cp "$CONF_RESTORE"/rclone.conf /root/.config/rclone/
[ -d "$CONF_RESTORE" ] && cp "$CONF_RESTORE"/research-*.service /etc/systemd/system/
[ -d "$CONF_RESTORE" ] && cp "$CONF_RESTORE"/research-*.timer /etc/systemd/system/
systemctl daemon-reload

# 5. 重新安装（确保 Nginx 配置也回滚）
sudo bash install.sh

# 6. 启动并验证
systemctl start research-*
sudo bash verify.sh
```

## 4. 卸载

### 4.1 安全卸载（保留数据）

```bash
sudo bash uninstall.sh
```

默认行为：

- ✅ 停止所有服务
- ✅ 移除 systemd 单元文件
- ✅ 移除 Nginx 站点配置
- ❌ **不删除** `$INSTALL_ROOT`（含数据库）
- ❌ **不删除** `/etc/research-app/env`（配置文件）

### 4.2 彻底卸载（含数据）

```bash
sudo bash uninstall.sh --purge
```

额外行为：

- ✅ 删除 `$INSTALL_ROOT` 整个安装目录（**含数据库，不可恢复**）
- ✅ 删除 `/etc/research-app/env` 配置文件
- ⚠️ **需要手动输入 `YES` 二次确认**

> ⚠️ `--purge` 不可逆。建议先备份再执行。

## 5. 灾难恢复演练清单

建议在系统上线后，定期（如每个月）进行一次灾难恢复演练：

```text
□ 步骤 1：执行备份脚本并验证备份文件正确
   sudo bash scripts/backup.sh
   ls -lh $INSTALL_ROOT/backups/

□ 步骤 2：备份完整性检查
   tar tzf $INSTALL_ROOT/backups/backup_*.tar.gz | head

□ 步骤 3：模拟卸载
   sudo bash uninstall.sh
   （保留 --purge 选项，确认数据目录存在）

□ 步骤 4：重新安装
   sudo bash install.sh
   （确认幂等：现运行库不应被清空）

□ 步骤 5：验证所有服务恢复并正常运行
   sudo bash verify.sh

□ 步骤 6：数据验证
   检查数据库记录数是否与备份前一致
```
