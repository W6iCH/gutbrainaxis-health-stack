# 常见故障排查

> 适用版本：gutbrainhealth-stack 一键部署包（2026-09 发布版）
> 最后更新：2026-09-16
> 前置阅读：[`安装说明.md`](./安装说明.md)

本文档按「症状 → 可能原因 → 定位命令 → 处置」格式，覆盖系统运行中最常见的故障场景。

---

## 1. 安装类故障

### 1.1 安装脚本报「仅支持 Ubuntu 22.04 / 24.04」

| 项目 | 说明 |
|------|------|
| **症状** | 执行 `install.sh` 直接报错退出 |
| **可能原因** | 服务器系统版本不在支持列表内；或 `/etc/os-release` 异常 |
| **定位命令** | `cat /etc/os-release` |
| **处置** | ① 确认系统为 Ubuntu 22.04/24.04；② 若版本正确但解析失败，检查 `/etc/os-release` 文件是否被修改；③ 使用 `lsb_release -a` 交叉验证 |

### 1.2 `apt-get update` 失败

| 项目 | 说明 |
|------|------|
| **症状** | 安装过程在「安装系统依赖」阶段卡住或报错 |
| **可能原因** | 网络不通；软件源不可达；DNS 解析失败 |
| **定位命令** | `ping -c 3 archive.ubuntu.com`；`curl -I http://archive.ubuntu.com` |
| **处置** | ① 检查网络连通性；② 检查 `/etc/apt/sources.list` 是否正确；③ 配置代理或更换软件源镜像 |

### 1.3 磁盘空间不足

| 项目 | 说明 |
|------|------|
| **症状** | 安装中报 `No space left on device` |
| **可能原因** | 磁盘分区空间不足；`/var/log` 日志膨胀 |
| **定位命令** | `df -h`；`du -sh /var/log/* | sort -hr \| head -20` |
| **处置** | ① 清理旧日志；② 扩容磁盘分区；③ 清理 `apt` 缓存（`sudo apt clean`） |

## 2. 服务类故障

### 2.1 服务起不来（systemd 失败）

| 项目 | 说明 |
|------|------|
| **症状** | 某个 `research-*` 服务状态为 `failed` 或反复 `auto-restart` |
| **可能原因** | 端口被占用；配置文件缺失；依赖的服务未启动；Python 依赖未安装 |
| **定位命令** | `systemctl status research-<service>`；`journalctl -u research-<service> -n 100` |
| **处置** | ① 查看 journal 日志定位具体报错；② 检查端口占用：`ss -tlnp \| grep <port>`；③ 确认配置文件存在且格式正确；④ 修复后执行 `systemctl restart research-<service>` |

### 2.2 端口被占用

| 项目 | 说明 |
|------|------|
| **症状** | 服务日志报 `Address already in use` |
| **可能原因** | 之前启动的进程未关闭；端口被其他程序占用 |
| **定位命令** | `ss -tlnp | grep :<port>`；`lsof -i :<port>`；`fuser <port>/tcp` |
| **处置** | ① 使用 `ss -tlnp` 找出占用进程的 PID；② 确认后可 `kill <PID>` 释放端口；③ 或在管理控制台/配置文件中修改端口 |

### 2.3 服务启动后立即退出

| 项目 | 说明 |
|------|------|
| **症状** | 服务已 enable，但启动 1–2 秒后退出 |
| **可能原因** | Python 语法错误；依赖模块缺失；配置文件路径错误 |
| **定位命令** | `journalctl -u research-<service> -n 50 --no-pager` |
| **处置** | ① 查看日志末尾的错误堆栈；② 确认虚拟环境的依赖已安装（见 §5.1）；③ 手动运行服务二进制确认报错 |

## 3. 网络与访问类故障

### 3.1 Nginx 502 Bad Gateway

| 项目 | 说明 |
|------|------|
| **症状** | 浏览器访问域名显示 502 |
| **可能原因** | 后端服务未运行；后端端口与 Nginx `proxy_pass` 不一致；后端进程崩溃 |
| **定位命令** | `systemctl status research-*`；`curl -I http://127.0.0.1:<后端端口>`；`tail -50 /var/log/nginx/error.log` |
| **处置** | ① 确认后端服务运行中；② 用 curl 直接访问后端端口验证；③ 检查 Nginx 配置中的端口是否与后端一致 |

### 3.2 Nginx 404 Not Found

| 项目 | 说明 |
|------|------|
| **症状** | 访问某个子域名返回 404 |
| **可能原因** | 域名未匹配到对应 server 块；DNS 解析错误；Nginx 配置未加载 |
| **定位命令** | `nginx -T \| grep server_name`；`dig <域名>` |
| **处置** | ① 确认 DNS 的 A 记录指向服务器 IP；② 检查 Nginx 中对应 server 块是否存在；③ 确认配置已 `nginx -s reload` |

### 3.3 Nginx 403 Forbidden

| 项目 | 说明 |
|------|------|
| **症状** | 静态文件或目录返回 403 |
| **可能原因** | 文件权限不足；目录索引未开启；SELinux/AppArmor 拦截 |
| **定位命令** | `ls -la <目录>`；`namei -l <文件路径>` |
| **处置** | ① 检查 Nginx 运行用户对文件/目录的读权限；② 调整目录权限（如 `chmod 755`、`chown www-data:www-data`）；③ 检查 SELinux 日志：`ausearch -m avc -ts recent` |

### 3.4 管理控制台登录后返回 401

| 项目 | 说明 |
|------|------|
| **症状** | 登录表单提交后提示「未授权」 |
| **可能原因** | 口令错误；会话 Cookie 过期；服务端密钥变更 |
| **处置** | ① 确认口令无误；② 清除浏览器 Cookie 后重试；③ 若改过 `SECRET_KEY`，需重新登录全部会话 |

## 4. 数据类故障

### 4.1 数据库文件损坏或不可写

| 项目 | 说明 |
|------|------|
| **症状** | 服务日志报 `sqlite3.OperationalError` 或 `readonly database` |
| **可能原因** | 磁盘空间满；文件权限错误；数据库文件被外部程序锁定 |
| **定位命令** | `df -h`；`ls -la <db文件>`；`sqlite3 <db> "PRAGMA integrity_check;"` |
| **处置** | ① 确认磁盘有足够空间；② 确保运行用户对 db 文件及所在目录有写权限；③ 用 `PRAGMA integrity_check` 检查完整性；④ 如损坏，用备份恢复（见 `升级备份与回滚.md`） |

### 4.2 问卷同步无新数据

| 项目 | 说明 |
|------|------|
| **症状** | 问卷平台有新提交，但数据库无新增记录 |
| **可能原因** | 同步定时器未触发；Token 失效；网络无法访问问卷平台 |
| **定位命令** | `systemctl list-timers \| grep research`；`systemctl status research-survey-sync.timer`；`curl -I <问卷平台URL>` |
| **处置** | ① 确认 timer 启用且最近有触发记录；② 检查 `journalctl -u research-survey-sync` 日志；③ 检查 Token 是否过期，重新配置 |

### 4.3 邮件发送失败

| 项目 | 说明 |
|------|------|
| **症状** | 邮件队列堆积，日志报 SMTP 错误 |
| **可能原因** | SMTP 服务器不可达；认证失败；被邮件服务商限流 |
| **定位命令** | `tail -100 $INSTALL_ROOT/logs/email_*.log`；`nc -vz <SMTP_HOST> 465` |
| **处置** | ① 检查 SMTP 主机/端口连通性；② 检查用户名/密码是否正确；③ 若限流，检查发送频率或更换邮件通道 |

## 5. 环境与依赖类故障

### 5.1 Python 虚拟环境依赖缺失

| 项目 | 说明 |
|------|------|
| **症状** | 服务日志报 `ModuleNotFoundError: No module named 'xxx'` |
| **可能原因** | venv 被删除；依赖未安装完整；Python 版本不匹配 |
| **定位命令** | `$INSTALL_ROOT/venv/bin/pip list` |
| **处置** | ① 对比 `requirements.txt` 检查缺失包；② 重新执行安装步骤中的依赖安装；③ 必要时重建 venv |

### 5.2 服务以错误的 Python 运行

| 项目 | 说明 |
|------|------|
| **症状** | 服务启动报 Python 版本错误（如 `SyntaxError` 或版本依赖不兼容） |
| **可能原因** | systemd 的 `ExecStart` 未指向 venv 中的 Python |
| **定位命令** | `systemctl cat research-<service> \| grep ExecStart` |
| **处置** | 确认 `ExecStart` 中 Python 路径为 `$INSTALL_ROOT/venv/bin/python3`，而不是系统 `/usr/bin/python3` |

### 5.3 系统时间不同步

| 项目 | 说明 |
|------|------|
| **症状** | HTTPS 证书校验失败；日志时间错乱 |
| **可能原因** | NTP 未配置或同步失败 |
| **定位命令** | `timedatectl status` |
| **处置** | `sudo timedatectl set-ntp true`，或手动 `sudo ntpdate ntp.ubuntu.com` |

## 6. 如何收集诊断信息

### 6.1 一键收集诊断包

```bash
# 收集系统状态、服务日志、配置检查等信息到当前目录
sudo bash verify.sh --collect
```

该命令会生成 `diagnostics_<时间戳>.tar.gz`，包含：

- 所有 `research-*` 服务的运行状态
- 各服务 journal 日志尾部（默认 200 行）
- 端口监听列表
- 配置文件存在性检查
- 磁盘空间与系统负载

### 6.2 常用诊断命令速查

```bash
# 查看所有服务状态
systemctl status research-*

# 查看特定服务日志（实时跟踪）
journalctl -u research-survey-feedback -f

# 查看服务日志最近 200 行
journalctl -u research-survey-feedback -n 200 --no-pager

# 查看端口监听
ss -tlnp | grep -E ':(8000|8001|9000|9876|8090|18789)'

# 查看 Nginx 错误日志
tail -100 /var/log/nginx/error.log

# 查看安装日志
tail -100 $INSTALL_ROOT/logs/install.log
```

## 7. 其他常见问题

| 症状 | 可能原因 | 处置 |
|------|----------|------|
| 服务器重启后服务不自动启动 | systemd 服务未 enable | `systemctl enable research-*.service` |
| 网页加载慢 | 网络/带宽问题 | 检查 `top`、`free -h` 系统资源 |
| HTTPS 证书过期 | Let's Encrypt 续期失败 | `sudo certbot renew` 并检查续期定时任务 |
| 中文字符乱码 | SSH 终端编码 | 设置 `LANG=zh_CN.UTF-8`，使用支持 UTF-8 的终端 |
| 修改配置后不生效 | 服务未重启 | 在管理控制台「进程开关」中重启对应服务 |
