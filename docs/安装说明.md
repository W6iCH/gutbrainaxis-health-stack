# 安装说明

> 适用版本：gutbrainaxis-health-stack 一键部署包（2026-09 发布版）
> 最后更新：2026-09-16
> 前置阅读：[`../README.md`](../README.md)

本文档介绍如何在一台全新 Ubuntu 服务器上安装「个性化饮食干预」课题服务端系统。

---

## 1. 前置条件

### 1.1 服务器要求

| 项目 | 最低要求 | 推荐 |
|------|----------|------|
| 操作系统 | Ubuntu 22.04 / 24.04 LTS | Ubuntu 24.04 LTS |
| 架构 | aarch64 / x86_64 | aarch64（与当前服务器一致） |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 20 GB 可用空间 | 50 GB +（含数据增长） |
| 权限 | root 或 sudo | — |

> ⚠️ 仅支持 Ubuntu 22.04 和 24.04。其他发行版（CentOS、Debian 等）需要手动适配安装脚本。

### 1.2 网络要求

- **出站网络**：需要访问以下目标
  - `apt.archive.ubuntu.com` / Ubuntu 软件源（安装系统依赖）
  - PyPI（安装 Python 依赖）
  - `wj.sjtu.edu.cn`（问卷数据同步）
  - SMTP 服务器（发送邮件反馈）
  - LLM API 服务（如 OpenAI 兼容接口）
  - 云盘存储服务（备份，可选）
- **入站网络**：对外开放以下端口

| 端口 | 用途 | 建议暴露范围 |
|------|------|-------------|
| 80 | Nginx（反向代理入口） | 公网（配合 HTTPS） |
| 443 | Nginx HTTPS | 公网 |
| 8000 | 问卷反馈服务（内部） | 仅本机/内网 |
| 8001 | 饮食反馈服务（内部） | 仅本机/内网 |
| 9000 | 管理控制台（内部） | 仅本机/内网 |
| 9876 | Webhook 接收器（内部） | 按需暴露 |

> 🔒 安全建议：所有业务端口**不要直接暴露公网**，仅通过 Nginx 80/443 入口访问。

### 1.3 DNS 准备

如需通过域名访问，请预先配置以下 A 记录，全部指向服务器 IP：

| 子域名 | 用途 |
|--------|------|
| `www.example.com` | Web 前端（问卷反馈页面） |
| `api.example.com` | API 服务 |
| `svc.example.com` | 饮食反馈服务 |
| `admin.example.com` | 管理控制台 |
| `tools.example.com` | Webhook 工具 |

> 示例中的域名 `example.com` 为占位符，部署时替换为真实域名。

## 2. 准备工作

### 2.1 获取部署包

将部署包上传至服务器（推荐放在 `/opt` 下），并解压：

```bash
# 方式一：git 克隆（如有私有仓库）
git clone <YOUR_REPO_URL> /opt/gutbrainaxis-health-stack

# 方式二：上传压缩包
scp gutbrainaxis-health-stack.tar.gz root@<SERVER_IP>:/opt/
cd /opt && tar xzf gutbrainaxis-health-stack.tar.gz
```

### 2.2 检查部署包结构

```bash
cd /opt/gutbrainaxis-health-stack
ls

# 应看到以下关键目录/文件：
#   install.sh          一键安装脚本（推荐入口）
#   uninstall.sh        卸载脚本
#   scripts/            辅助脚本（init_db.py 等）
#   services/           五套服务源码
#   systemd/            14 个 systemd 单元
#   nginx/              Nginx 站点配置模板
#   config/             配置模板（*.example）
#   tools/              发布前检查工具
```

## 3. 安装三步

### 第 1 步：克隆部署包

```bash
git clone <YOUR_REPO_URL> /opt/gutbrainaxis-health-stack
cd /opt/gutbrainaxis-health-stack
```

### 第 2 步：预览将要执行的动作（可选但推荐）

```bash
sudo bash install.sh --dry-run
```

`--dry-run` 模式会**逐条打印**将要执行的安装步骤，但**不会**实际修改系统。输出示例：

```
[DRY-RUN] apt-get update
[DRY-RUN] apt-get install -y python3 python3-venv python3-pip nginx sqlite3 curl
[DRY-RUN] python3 -m venv /opt/gutbrainaxis/venv
...
```

检查输出无误后，进入正式安装。

### 第 3 步：正式安装

```bash
sudo bash install.sh
```

安装过程大约需要 3–10 分钟（取决于网络速度），包含以下阶段：

1. **安装系统依赖**：`python3`、`nginx`、`sqlite3` 等
2. **创建虚拟环境**：在 `$INSTALL_ROOT/venv` 下创建 Python 虚拟环境
3. **安装 Python 依赖**：Flask、aiohttp、openai 等
4. **复制服务代码**：将 `services/` 下的五个服务复制到安装目录
5. **初始化数据库**：运行 `scripts/init_db.py` 创建空 schema
6. **生成配置文件**：从 `config/*.example` 生成真实配置到 `/etc/research-app/env`（权限 600）
7. **安装 systemd 单元**：注册 14 个 systemd 单元文件
8. **安装 Nginx 配置**：将 `nginx/research-app.conf` 安装到 `/etc/nginx/`
9. **启动服务**：启用并启动所有 systemd 服务

### 安装完成的标志

安装脚本末尾会输出类似信息：

```
✅ 安装完成
   安装目录: /opt/gutbrainaxis
   日志:     /opt/gutbrainaxis/logs/install.log
```

## 3. 安装参数

安装脚本支持以下参数：

| 参数 | 说明 |
|------|------|
| `--dry-run` | 仅预览，不实际执行 |
| `--prefix=/path` | 自定义安装目录（默认 `/opt/gutbrainaxis`） |

示例：

```bash
# 安装到自定义目录
sudo bash install.sh --prefix=/srv/gutbrainaxis

# 查看帮助
sudo bash install.sh --help
```

> ✅ 提示：`bash install.sh --help` 会输出所有受支持的参数，以脚本实际实现为准。

## 4. 安装后配置

安装完成后，还需完成以下手动配置步骤：

### 4.1 填写真实凭据

安装脚本生成的配置文件保存在 `/etc/server-config/config.env`：

```bash
sudo nano /etc/server-config/config.env
```

**必须手动填写的项目：**

| 变量 | 说明 |
|------|------|
| `SMTP_PASSWORD` | SMTP 邮箱密码 |
| `LLM_API_KEYS` | LLM API Key 列表（逗号分隔） |
| `ALERT_SMTP_PASSWORD` | 告警专用 SMTP 密码 |
| `WJX_SURVEY_TOKEN` | 问卷平台令牌 |
| `WJX_DIET_TOKEN` | 饮食问卷平台令牌 |

> ⚠️ 配置文件权限为 600，只允许 root 读取。填写完成前服务可能无法正常工作。

### 4.2 修改默认密码

安装时会生成一个随机初始密码，存放在：

```text
$INSTALL_ROOT/config/initial_password.txt   （权限 600）
```

首次登录管理控制台后立即使用「改密」功能更换密码。

### 4.3 重启服务使配置生效

```bash
sudo systemctl restart research-*
```

## 5. 验证安装

### 5.1 检查服务状态

```bash
sudo bash verify.sh
```

脚本将自动检查：

- ✅ 所有 systemd 服务是否运行
- ✅ 配置文件是否存在且无未替换占位符
- ✅ 数据库是否可读写
- ✅ 各服务 HTTP 端口是否响应

### 5.2 手动验证

```bash
# 查看所有服务状态
systemctl status research-*

# 查看服务列表
systemctl list-units 'research-*' --all

# 检查端口监听
ss -tlnp | grep -E ':(8000|8001|9000|9876)'
```

### 5.3 访问验证

| 地址 | 说明 |
|------|------|
| `http://<服务器IP>:9000` | 管理控制台（需登录） |
| `http://<服务器IP>:8000/health` | 问卷反馈服务健康检查 |
| `http://<服务器IP>:8001/ping` | 饮食反馈服务 Ping |
| `http://<服务器IP>:9876/health` | Webhook 健康检查 |

> 💡 如果通过 Nginx 域名访问，请使用对应的域名地址：`http://www.example.com` 等。

## 6. 安装日志与故障排查

### 6.1 安装日志

安装过程全部输出会同时写入：

```text
$INSTALL_ROOT/logs/install.log
```

### 6.2 常见安装失败

| 症状 | 可能原因 | 处置 |
|------|----------|------|
| `apt-get update` 失败 | 网络不通/软件源问题 | 检查 DNS 和网络连通性 |
| Python 包安装失败 | PyPI 网络问题 | 重试或配置国内镜像源 |
| `ERROR: 仅支持 Ubuntu 22.04` | 系统版本不符 | 更换系统或手动适配脚本 |
| 服务启动失败 | 依赖未安装/配置不完整 | 查看 `journalctl -u <service>` |

### 6.3 回滚

如需完全移除已安装的组件：

```bash
sudo bash uninstall.sh
```

> ⚠️ 注意：`uninstall.sh` 默认**保留数据目录**。如需彻底删除（含数据库），加 `--purge` 参数，且会要求二次确认。
