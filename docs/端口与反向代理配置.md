# 端口与反向代理配置

> 适用版本：gutbrainaxis-health-stack 一键部署包（2026-09 发布版）
> 最后更新：2026-09-16
> 前置阅读：[`安装说明.md`](./安装说明.md)

本文档说明本系统的默认端口分配、域名映射规则，以及如何通过 Nginx 配置反向代理与 HTTPS。

---

## 1. 端口分配总表

以下是系统默认的端口分配。**所有端口均监听 127.0.0.1 或内网**，不直接暴露公网。

| 端口 | 协议 | 服务 | 用途 | 是否可改 |
|------|------|------|------|----------|
| 80 | HTTP | Nginx | 反向代理入口 / HTTP 跳转 | 推荐保持 |
| 443 | HTTPS | Nginx | 反向代理入口（启用 TLS 后） | 推荐保持 |
| 8000 | HTTP | 问卷反馈服务 | 问卷提交 + 个人报告 + 评分 API | ✅ 可改 |
| 8001 | HTTP | 饮食反馈服务 | 饮食建议 + 反馈报告 | ✅ 可改 |
| 8080 | HTTP | Web 前端 | 问卷前端页面（经 Nginx 代理） | ✅ 可改 |
| 8090 | HTTP | 数据看板（预留） | 研究者数据看板 | ✅ 可改 |
| 9000 | HTTP | 管理控制台 | 配置/进程/端口/自检/审计 | ✅ 可改 |
| 9876 | HTTP | Webhook 接收器 | 接收问卷平台事件推送 | ✅ 可改 |
| 18789 | HTTP | Node.js 服务（可选） | 附加服务（如非必需可关闭） | ✅ 可改 |

### 1.1 端口对应关系

```
Internet / 内网
      │
      ▼
  Nginx :80 / :443
      │
      ├─→ 8000  问卷反馈服务
      ├─→ 8001  饮食反馈服务
      ├─→ 8080  Web 前端
      ├─→ 8090  数据看板（预留）
      ├─→ 9000  管理控制台
      ├─→ 9876  Webhook 接收器
      └─→ 18789 Node.js 服务（可选）
```

## 3. 修改端口

> 推荐通过**管理控制台**修改端口，系统会自动完成 Nginx 配置更新与冲突检测。
> 以下为手工修改方式，适用于无法使用控制台的情况。

### 3.1 手工修改端口步骤

#### ① 修改环境变量

编辑 `/etc/server-config/env` 中的对应端口：

```bash
sudo nano /etc/server-config/env
```

示例（将问卷反馈服务从 8000 改为 8010）：

```
SURVEY_FEEDBACK_PORT=8010
```

#### ② 修改 systemd 单元（如端口硬编码）

```bash
sudo nano /etc/systemd/system/research-survey-feedback.service
# 修改 ExecStart 中的端口参数

sudo systemctl daemon-reload
```

#### ③ 修改 Nginx 配置

编辑 Nginx 站点配置中的 `proxy_pass`：

```bash
sudo nano /etc/nginx/sites-available/research-app.conf
# 将 proxy_pass http://127.0.0.1:8000 改为 http://127.0.0.1:8010
```

#### ④ 校验并重启

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl restart research-survey-feedback
```

### 3.2 端口冲突排查

修改端口后若服务起不来：

```bash
# 查看端口是否已被占用
ss -tlnp | grep -E ':(8010)'

# 查看服务状态
systemctl status research-survey-feedback

# 查看服务日志
journalctl -u research-survey-feedback -n 50
```

## 4. Nginx 配置说明

### 4.1 配置文件位置

系统安装时会将 `nginx/research-app.conf` 模板安装到：

```text
/etc/nginx/sites-available/research-app.conf
```

并创建符号链接：

```text
/etc/nginx/sites-enabled/research-app.conf → /etc/nginx/sites-available/research-app.conf
```

### 4.2 配置文件结构

配置文件包含以下 server 块：

| server_name | 功能 |
|-------------|------|
| `example.com` | 裸域 301 跳转 |
| `www.example.com` | Web 前端 → 8080 |
| `api.example.com` | API → 8000 |
| `svc.example.com` | 饮食反馈 → 8001 |
| `admin.example.com` | 管理控制台 → 9000 |
| `tools.example.com` | Webhook → 9876 |
| `data.example.com` | 数据看板 → 8090 |

每个 server 块的核心配置模板如下：

```nginx
server {
    listen 80;
    server_name api.example.com;
    access_log /var/log/nginx/api.access.log;
    error_log  /var/log/nginx/api.error.log;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
```

> ⚠️ `server_names_hash_bucket_size 64;` 已在配置顶部声明，用于支持超长域名匹配。若修改了域名数量或长度，请保持该字段。

### 4.3 修改域名示例

假设要把占位域名 `example.com` 换成你自己的域名（下文以 `yourlab.example.com` 为例）：

1. 修改所有 server 块中的 `server_name` 字段；
2. 修改裸域跳转的目标；
3. 更新 DNS 记录；
4. 校验并重载：

```bash
sudo nginx -t
sudo nginx -s reload
```

## 5. HTTPS / SSL 证书配置

### 5.1 方案一：Certbot（推荐，自动续期）

```bash
# 安装 certbot
sudo apt-get install -y certbot python3-certbot-nginx

# 为所有子域名申请证书（一次性申请多个 -d 域名）
sudo certbot --nginx -d example.com \
  -d www.example.com \
  -d api.example.com \
  -d svc.example.com \
  -d admin.example.com \
  -d tools.example.com \
  -d data.example.com
```

Certbot 会自动：

- 获取 Let's Encrypt 证书；
- 修改 Nginx 配置添加 TLS 块；
- 配置 HTTP → HTTPS 跳转；
- 设置自动续期（`certbot renew`）。

### 5.2 方案二：已有证书（手动配置）

将证书文件放置到服务器后，在对应的 server 块中添加：

```nginx
server {
    listen 443 ssl http2;
    server_name admin.example.com api.example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    location / {
        proxy_pass http://127.0.0.1:9000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

### 5.3 验证 HTTPS

```bash
# 校验配置语法
sudo nginx -t

# 重载配置
sudo systemctl reload nginx

# 用 curl 验证
curl -I https://admin.example.com
```

## 6. 防火墙配置

如果启用了 UFW 或其他防火墙，需要放行以下端口：

```bash
# 放行 HTTP/HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# 如需要通过公网直接访问管理控制台（不推荐），放开 9000
# sudo ufw allow 9000/tcp
```

> ⚠️ 内部服务端口（8000/8001/9876/8090）建议**不要**对外开放，仅通过 Nginx 代理访问。

## 7. 常见问题

### Q1：`nginx -t` 报 `server_names_hash_bucket_size` 错误？

检查配置顶部是否包含 `server_names_hash_bucket_size 64;`，若无则添加后重试。

### Q2：修改端口后 Nginx 502 Bad Gateway？

- 确认后端服务是否已重启并监听新端口：`ss -tlnp | grep <新端口>`
- 确认 Nginx 中的 `proxy_pass` 地址与实际端口一致

### Q3：如何查看 Nginx 访问日志？

```bash
tail -f /var/log/nginx/access.log
tail -f /var/log/nginx/error.log
```

### Q4：证书即将到期如何续期？

```bash
sudo certbot renew --dry-run   # 先模拟续期
sudo certbot renew             # 实际续期
```
