# 分析口径一致性核对（部署包 ⟷ 课题科研处理）

> 目的：回答用户硬性要求「程序内所有分析必须与课题研究处理一致」——**逐项**核对
> 部署包（`12_部署包_可发布/`）与科研侧（`13_问卷原始数据_20260916/`、`14_评分标准/`、
> `06_分析实施与整合结果/`、`09_整合处理_新Agent/`）的口径，给出**差异清单与处理结论**。
>
> 核对日期：2026-09-16 ｜ 科研侧全部**只读**，未做任何修改。
>
> 结论速览：**计分口径已逐条等价（可 CI 验证）；饮食营养量化 / 完成度赋分 / 统计推断
> 三类口径「部署包不做科研级计算」，属职责边界而非口径冲突——已在本文逐条写明，

## 一、计分（量表 + BMI）——**已逐条等价**（硬性要求，已落地为门禁）

| 项 | 内容 |
|---|---|
| 权威依据 | `14_评分标准/00_评分标准_权威版.md`（规则文本）＋ `14_评分标准/03_条目库_修正/survey_scoring_native.py`（可执行条目库） |
| 部署包实现 | `services/sjtu_survey_pro/survey_scoring.py`（权威条目库逐字 + 兼容层） |
| 验证手段 | `tools/verify_scoring_parity.py`（同一份输入双跑，逐条断言） |
| 断言范围 | **L1 条目级**（每条目 × 每个合法作答，含矩阵各 `option_idx`、反向条目、未收录标签、非计分题、未知题）；**L2 量表级**（合成答卷 min/max/mid/mixed 四套，比对 10 量表 + BMI 的 total / n_items / n_expected / 分档 / 子量表 / 分领域 / PSQI 成分 / IPAQ MET / BMI 分档）；**L3 常量级**（分档切点、反向集合、领域归属、期望题数、非计分集合、CHOICE_RULES、MATRIX_RULES）；**L4 缺失与严格模式**（缺条目、未收录标签异常类型、空答卷） |
| 实测结果 | **1771 项断言全部相等**（`ok=True`，退出码 0） |
| 唯一差异 | 4 条**元数据**差异（`min/max/mid/mixed` 四套答卷各 1 条）：程序侧 PSQI 字典多出展示用 `max_score=21`（=3×成分数 7，与权威隐含上限一致）。**不携带分值语义、不影响任何分数**，已在报告中单独标注为「元数据差异」而非失败项。 |
| CI 门禁 | `tools/selfcheck.py` 的 `parity` 组（`parity.compare`）；权威库缺失时 `skip`（生产服务器正常），仓库工作区内则**必跑**。 |

**结论**：计分口径**逐条等价**，权威库为准。

## 二、饮食抽取与营养量化——**职责边界不同，不冲突**

| 维度 | 科研侧（`06_分析实施与整合结果/11_分析实施/记录抽取`） | 部署包侧（`services/diet_survey/`） | 结论 |
|---|---|---|---|
| 目标 | 把中文饮食记录**结构化**并量化成 8 营养素 + 12 食物组 | 采集记录、入库、生成**即时反馈邮件**（LLM 建议） | 不冲突 |
| 抽取 | LLM 抽取（`extract_all.jsonl` 1,296 人-日；`extract_qwen.jsonl` 10% 双模型复核） | 原样保存 `diet_description` 文本 | 部署包**不做**结构化抽取 |
| 营养锚定 | `exact/synonym/contain/cook_strip/template` 五法锚定中国食物成分表；输出 kcal 与 8 营养素 | **不计算** kcal / 营养素 / 食物组 | 部署包**不产生**科研营养数值 |
| 参考文件 | — | `food_nutrition.csv`、`dish_nutrition_calculated.csv` | **仅随仓库发布的参考数据**（当前无任何代码消费，见 `功能与进程清单.md` B6） |
| 人-日去重 | 同 `(student_id, record_date)` 多行 → 保留 **max(id)**（最新提交）；1,445 → 1,296 | 按 `submission_id UNIQUE` 入库（同一次提交不重复） | **去重键不同**：若直接用部署包库做科研分析，须改走「按人-日保留最新」口径 |
| 窗口 | 2026-07-06 ~ 07-29 | 无内置窗口（按拉取周期持续入库） | 科研窗口由科研脚本施加 |
| 剔除 | 研究者账号 `523111910046`（3 条） | **无**该剔除逻辑 | 科研剔除规则属研究侧决定，**不宜写进面向运行期的部署包** |

**结论**：
1. 部署包**不做**科研级营养量化 → 二者**不存在数值口径冲突**；
2. 但**不得**把部署包内的饮食数据当作科研营养/食物组数据源；
3. 若未来要用部署包库做科研分析，必须先施加「窗口 + 剔除研究者 + 人-日保留 max(id)」三项口径。

## 三、完成度 / 依从性——**定义不同，已显式标注，禁止混用**

| 口径 | 定义 | 位置 | 用途 |
|---|---|---|---|
| 部署包「目标完成度」 | **赋分制**：量表 3 次（上限 10 分）＋ 运动 3 次×1 分 ＋ 饮食 22 天×1 分 = **35 分**；绿 ≥85%、黄 ≥50%；宽限 3 天 | `services/common/lib_study.py: DEFAULT_CALENDAR["completion"]` | **控制台显示**受试者完成进度 |
| 部署包「依从性时序」 | **提交制**：逐人逐日「任一链路是否提交」的 0/1 矩阵 + 分链路完成率趋势 | `services/data_dashboard/ops.py: adherence_series()` | **运行期运营指标** |
| 科研「记录依从性」 | 记录完成率（%，24 天主窗口，`follow_rate`） | `06_.../FFQ/FFQ_指数_宽表.csv`、`12_整合分析/tables/02_adherence_dose.csv` | **科研统计** |
| 科研「建议落实率」 | 由 LLM 自评的落实比例 | `09_整合处理_新Agent/06_质量自检报告_v3.md` A8 | **已被明确降级**：无独立人工复核前「不得称 adherence」，只能叫 *LLM-rated recommendation completion / process indicator* |

**结论**：
1. 部署包的两个指标都是**提交/赋分**口径，**与科研的 `follow_rate` 不是同一个量**，不可互相替代；
2. 部署包**未**把 LLM 自评落实率标为 adherence（符合科研侧的降级要求）；
3. 已在 `lib_study.py` 注释中显式标注「本口径仅供控制台显示，科研口径见本文」，避免误用。

## 四、统计推断口径——**部署包不做科研统计**

| 维度 | 科研侧 | 部署包侧 | 结论 |
|---|---|---|---|
| 统计方法 | 混合模型 / FDR 校正 / 配对 bootstrap（seed=42，9,999 次）/ Spearman + OLS 等 | 计数、比率、趋势（无假设检验、无多重比较校正） | 部署包**不做**推断统计 |
| 数值真源 | `14_评分标准/outputs/D5_三口径对照_*.csv`、`09_整合处理_新Agent/.../数字溯源对照表.md` | 无（仅运行期指标） | 科研数字**不得**取自部署包看板 |

**结论**：部署包看板是**运营监控**，不是科研统计工具；论文数字一律以科研侧锁定 CSV 为准。

## 五、饮食/运动题库与「三链路」结构

* 三链路（量表 226 份 / 饮食 1,495 份 / 运动 175 份）在部署包中按三套独立服务 + 三套库落地，
  与科研侧「三个问卷项目」结构一致；
