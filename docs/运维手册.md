## 0. 五分钟上手

```bash
export APP_BASE=/opt/gutbrainaxis
export PY=$APP_BASE/.venv/bin/python3        # install.sh 建的 venv
cd $APP_BASE

# 一页看全：配置 / 服务 / 端口 / 库 / 盘 / 外部依赖 / 模拟残留
$PY tools/selfcheck.py

# 只关注运行面
$PY tools/selfcheck.py --only ports,http,database,webhook

# 机器可读（可接监控）
$PY tools/selfcheck.py --json --report /tmp/selfcheck.json
```

退出码：`0`=全通过；`1`=有失败项；`2`=配置无法加载。

## 5. 密钥与安全

| 事项 | 做法 |
|---|---|
| 密钥存放 | **只**放 `/etc/research-app/secrets.env`（`0600`）；`app.yaml` 里只写 `${VAR}` 引用 |
| 密钥轮换 | 编辑 `secrets.env` → `systemctl restart` 受影响服务；问卷 Token 需**同时在平台侧吊销旧的** |
| 发布前 | `python3 tools/scan_sensitive.py` 必须 `0 阻断项`（CI 已含） |
| 控制台口令 | 首启随机生成（`initial_password.txt`，0600）并**强制改密**；强度要求 ≥10 位含字母数字 |
| 登录爆破 | 失败 5 次锁 15 分钟，**锁定状态持久化**（重启不可绕过） |
| Cookie | `HttpOnly` + `SameSite=Lax`；HTTPS 下置 `Secure`（`CONSOLE_COOKIE_SECURE=1`） |
| CSRF | 所有写操作需 `X-CSRF-Token`（SPA 外壳注入） |
| 审计 | `/opt/gutbrainaxis/logs/console_audit.log`（含配置/进程/端口/调度变更） |

## 6. 故障处置（按症状）

| 症状 | 首选动作 |
|---|---|
| 看板某页 500 | `journalctl -u research-data-dashboard`；`tools/selfcheck.py --only database` |
| 简历（报告）页 403 | 正常：仅允许 `/report?user&quest&answer`；其他路径一律拒绝 |
| 邮件发不出 | `selfcheck.py --only external`；检查 `secrets.env` 的 SMTP 项；看 `.email_queue/failed/` |
| LLM 队列不动 | `diet_llm_queue.py --status` 看 `waiting_window` —— `offpeak`/`hybrid` 模式下**窗口外不动是设计** |
| 数据「不更新」 | 看 webhook `mode`；`timer_only` 时靠定时，最长滞后 = `schedule.survey_sync_minutes` |
| 磁盘将满 | `selfcheck.py --only storage`；`scripts/backup.sh` 保留份数由 `backup.retention` 决定 |
| 配置文件被改坏 | 控制台「调度」页写入前自动备份 `app.yaml.bak.<ts>`；或从 `config/app.yaml.example` 重建 |

更多见 `docs/常见故障排查.md`。

## 7. 指标与告警分级

* **健康端点**：每个服务 `GET /healthz`（含依赖检查）；看板「系统健康」页聚合全部服务 + 端口 + 库。
* **自检**：`tools/selfcheck.py`（CLI）与控制台「自检面板」**同一后端**，结果一致。
* **告警分级**（`alert.severity_threshold`，默认 `warning`）：

  | 级别 | 触发示例 | 静默时段行为 |
  |---|---|---|
  | `critical` | 服务不可用、数据库不可读、端口未监听、数据严重滞后 | **始终发送** |
  | `warning` | 队列积压、Webhook 长期无回调、外部依赖不可达 | 只落 `logs/alerts_quiet.log` |
  | `info` | 提示级 | 默认不发 |

* **告警去重**：同一告警在 `alert.cooldown_minutes` 内不重复发送；
  恢复后发「已消除」闭环通知。
* **静默时段**：`schedule.quiet_hours_*`（默认 22:30–07:00）；可用
  `alert.quiet_hours_*` 单独覆盖告警侧窗口。

## 8. 备份与恢复

```bash
sudo bash scripts/backup.sh              # 本地备份（tar.gz），保留 backup.retention 份
sudo bash scripts/rclone-backup.sh       # 远端（需 backup.remote_enabled + rclone 配置）
```

恢复步骤：
1. `systemctl stop research-*`;
2. 解包 `backups/<ts>.tar.gz` 覆盖 `$APP_BASE`（数据库、配置、单元）；
3. `sudo bash install.sh`（幂等，重建单元与权限）；
4. `tools/selfcheck.py` 确认全绿；
5. `systemctl start` 各服务。

> 备份**验证**：`backup.verify_after: true` 时，备份脚本会校验 tar 可读性与条目数；
> 失败会以 `critical` 级告警发出。
