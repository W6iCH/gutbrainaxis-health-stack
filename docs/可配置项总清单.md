## 一、怎么用

```bash
# 1) 查看/校验当前配置（缺项/类型错/越界/占位符 → 逐条报出键位置）
python3 tools/appconfig.py --config /etc/research-app/app.yaml --check

# 2) schema 与 example 键集合一致（发布门禁）
python3 tools/appconfig.py --check-example-keys

# 3) 把 app.yaml 渲染成 systemd 环境文件 / timer 周期（改配置即改行为）
python3 tools/appconfig.py --render-env /etc/research-app/env
python3 tools/appconfig.py --render-timers /etc/systemd/system

# 4) 生成/校验本清单（防文档漂移）
python3 tools/gen_config_doc.py && python3 tools/gen_config_doc.py --check
```

**生效方式总览**

| 生效方式 | 含义 |
|---|---|
| 热加载（≤30s） | 服务周期重读配置，无需重启 |
| 重启受影响服务 | `systemctl restart <unit>` |
| 重渲染 env + 重启 | 先 `--render-env`，再重启 |
| 重渲染 timer + daemon-reload | 先 `--render-timers`，再 `systemctl daemon-reload` |

密钥类配置（`secret: true`）**只写占位引用** `${VAR}`，真实值放 `/etc/research-app/secrets.env`（0600），仓库内零密钥。

## 三、三方一致性（schema ↔ yaml ↔ 实际读取）

* schema ↔ yaml：`--check-example-keys` 双向比对，当前 **180 键完全一致**；
* yaml → 实际读取：上表「生效方式」列末的 `` `ENV_VAR` `` 即注入各服务的环境变量名（由 `tools/appconfig.py: ENV_MAP` 渲染）；
* 实际读取 → yaml：自检项 `config.env_bridge` 反向扫描服务源码中 `os.environ.get("X")` 的用法，凡未在 `ENV_MAP` 中声明者即报错（防止「代码偷偷读了一个没人配的环境变量」）。

> 明细表共 **179** 项；与 schema 声明数（180）一致。
